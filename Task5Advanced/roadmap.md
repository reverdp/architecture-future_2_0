# Стратегический roadmap внедрения Data Mesh

## Цель внедрения Data Mesh

Data Mesh нужен, чтобы перейти от централизованной модели DWH к доменной модели управления данными

Ключевая идея:
- каждый домен владеет своими данными
- данные оформляются как data products
- Data Platform предоставляет общие инструменты
- бизнес-пользователи получают доступ к данным через self-service BI
- управление доступом, качеством и классификацией данных выполняется централизованно по единым правилам

## Ключевые роли

| Роль               | Ответственность                                                              |
|--------------------|------------------------------------------------------------------------------|
| Data Product Owner | Отвечает за ценность, качество и развитие data product в своём домене        |
| Data Engineer      | Строит пайплайны, витрины, события и интеграции данных                       |
| BI-аналитик        | Разрабатывает отчёты                                                         |
| Domain Architect   | Следит за границами домена, событиями и архитектурными решениями             |
| Platform Engineer  | Развивает общую Data Platform, CI/CD, observability, инфраструктуру          |
| Security           | Контролирует доступ, регуляторные требования и защиту чувствительных данных  |

## Roadmap на 3 года

| Период | Этап                                   | Основные работы                                                                                                                  | Бизнес-цель                                                                   |
|--------|----------------------------------------|----------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------|
| 1 год  | Пилот Data Mesh                        | Выбрать 1–2 домена, назначить Data Product Owner; описать первые data products; внедрить Data Catalog и базовые правила качества | Быстро показать ценность новой модели и снизить зависимость от ручных отчётов |
| 1 год  | Базовая Data Platform                  | Развернуть Data Lakehouse, брокер событий, базовый self-service BI, RBAC                                                         | Создать основу для масштабирования данных                                     |
| 1 год  | Масштабирование на критические домены  | Подключить Medical Services, Fintech Services, AI Diagnostics; описать доменные события и data products                          | Ускорить развитие медицинских, финтех и ИИ-сервисов                           |
| 2 год  | Self-service BI                        | Перевести основные отчёты в портал самообслуживания; обучить бизнес-пользователей                                                | Сократить время аналитиков и ускорить получение отчётов                       |
| 2 год  | Интеграция партнёров                   | Подключить фармацевтические компании и производителей оборудования через API и события                                           | Развитие новых бизнес направлений                                             |
| 2 год  | Снижение зависимости от DWH            | Перенести ключевые трансформации из DWH в доменные пайплайны и сервисы                                                           | Снизить технический долг и нагрузку на legacy                                 |
| 2 год  | Near-real-time витрины                 | Запустить потоковые витрины                                                                                                      | Повысить скорость реакции бизнеса                                             |
| 3 год  | Завершение масштабирования Data Mesh   | Все ключевые домены имеют владельцев, data products, события и SLA качества данных                                               | Масштабировать компанию по продуктам, регионам и источникам данных            |
| 3 год  | Вывод legacy из критического пути      | Убрать Camel и старый DWH из критичных интеграций, оставить только архивные или временные сценарии                               | Повысить гибкость и устойчивость архитектуры                                  |
