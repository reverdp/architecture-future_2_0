# TCO-анализ текущей и целевой архитектуры

Текущая архитектура опирается на:

- DWH на Microsoft SQL Server 2008
- PowerBuilder
- кастомизированную BI поверх DWH
- Apache Camel
- большое количество SQL-трансформаций
- ручную работу аналитиков
- сложную поддержку legacy

Целевая архитектура предполагает:

- облачную инфраструктуру
- доменные сервисы
- событийную платформу
- Data Lakehouse
- Data Mesh
- потоковую обработку данных
- постепенный отказ от legacy


## Основные статьи затрат

| Статья затрат    | Текущая архитектура                                                  | Целевая архитектура                                                      |
|------------------|----------------------------------------------------------------------|--------------------------------------------------------------------------|
| Инфраструктура   | Собственные/выделенные серверы, DWH, хранение больших объёмов данных | Облако, управляемые сервисы, объектное хранилище, ресурсы по потреблению |
| Лицензии         | SQL Server, Power BI, legacy-инструменты                             | Облачные сервисы, managed databases, observability                       |
| Сопровождение    | Высокая стоимость поддержки устаревших систем                        | Ниже за счёт managed-сервисов, но выше требования к DevOps               |
| Разработка       | Доработки DWH, Camel и кастомной BI                                  | Разработка доменных сервисов, событий, data products                     |
| Аналитики        | Много ручной подготовки отчётов и SQL-трансформаций                  | Больше self-service, меньше ручной подготовки типовых отчётов            |
| Интеграции       | Доработки центральной шины и DWH                                     | Подключение через события, API и контракты                               |
| Масштабирование  | Вертикальное масштабирование DWH, дорогое расширение                 | Горизонтальное масштабирование доменов и потоков                         |
| Миграция         | Нет миграционных затрат                                              | Существенные затраты в первые 1–2 года                                   |

## Оценочная модель TCO на 3 года

Оценка дана в относительных единицах, где текущая годовая стоимость владения принята за 100 единиц.

| Год   | Текущая архитектура | Целевая архитектура | Комментарий                                                                                                     |
|-------|--------------------:|--------------------:|-----------------------------------------------------------------------------------------------------------------|
| 1 год |                 100 |                 130 | Рост затрат из-за миграции, пилотов, обучения, параллельной поддержки старого и нового контуров                 |
| 2 год |                 110 |                 115 | Текущая архитектура дорожает из-за технического долга; целевая начинает снижать ручную работу и нагрузку на DWH |
| 3 год |                 120 |                  90 | Legacy постепенно выводится, self-service BI и потоковые витрины снижают операционные затраты                   |

## Сравнение TCO на горизонте трёх лет

| Архитектура           | 1 год | 2 год | 3 год | Итого за 3 года |
|-----------------------|------:|------:|------:|----------------:|
| Текущая архитектура   |   100 |   110 |   120 |             330 |
| Целевая архитектура   |   130 |   115 |    90 |             335 |

На горизонте трёх лет целевая архитектура может быть сопоставима или немного дороже по прямым затратам, потому что первый этап требует инвестиций в миграцию, платформу данных, обучение и параллельную поддержку.
Но основной экономический эффект появляется за счёт снижения косвенных потерь.

## Вывод по TCO

Целевая архитектура требует больших инвестиций на первом этапе, но снижает долгосрочные риски и операционные затраты
